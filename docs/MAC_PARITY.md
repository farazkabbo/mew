Current source inventory: `feature/macbook` at merge `98d57768fd8c2bb2e6dfbae7723ad70eab369af5`, incorporating `origin/main` `e2d8ccbd7eb68258640dc6ce114e2a025960f2b6`, 2026-11-25, plus the uncommitted Mac foundation described below. Historical checkpoint: `012418b`, desktop 0.1.7, 2026-11-21. The historical checkpoint is not the current Windows feature inventory. This is a source inventory and acceptance ledger, not a report of a completed Mac port. The owner requires **all Windows desktop features on Mac, including the Dynamic Island, music, Neb's Hand, DO IT, SHOW ME, CATCH ME and Handoff**. No feature is removed from the target, postponed to a later release, or replaced by a shell-only release in this ledger. An unresolved platform equivalent remains an open acceptance item. ## Evidence and scope

The current code takes precedence over old plans. Entry points are `desktop/src-tauri/src/lib.rs`, `screen/mod.rs`, `screen/coach.rs::on_hold`, and the bundled pages under `desktop/overlay-src` and `desktop/shell`. Owner decisions are in `CLAUDE.md`, `docs/HANDOFF.md`, `docs/SCREEN_COACH.md` (especially decisions 12–18), `docs/SCREEN_COACH_NOTES_CHECK.md`, `docs/NOTEBOOKS_K.md`, and `docs/NEB_APP_UI.md` (desktop overlays and later onboarding decisions). The current target also includes every binding decision in `docs/CURSOR_MODES.md` (M1–M6) and `docs/HANDOFF_FEATURE.md`; shared web/server implementations do not close their missing native Mac paths.

Status vocabulary:

- **Implemented, source inspected:** production code exists and is reachable on that platform. This does not prove an installed run.
- **Pending:** production Mac integration is absent or compiled out. Shared parsers, renderers and tests do not change this status.
- **Historical fixture evidence:** a local note reports a specific synthetic or packaged test from an earlier snapshot. It is not fresh verification of this baseline.
- **Verified here:** the static inventory plus the automated checks recorded below. Synthetic images, fake input sinks and stubbed browser IPC prove their stated boundaries only. Personal-screen capture, real native input, installed overlay interaction and Windows runtime parity remain unverified.

`screen/mod.rs` declares **26 Windows-only modules: 25 runtime/orchestration modules plus `win`**. `lib.rs` registers **49 Windows invoke handlers** and **22 Mac handlers** (shell, local island/drawing/settings and updater commands). `screen/win/mod.rs` exports **28 production submodules**, plus its test fixture. The shared `Surface` inventory has **13 surfaces**, including the clip preview; its non-preview overlay list contains 12 surfaces. In addition, Windows has a native per-monitor cursor layer, a native CATCH ME chip and a separate Handoff preview window; these are not covered by counting the 13 bundled surfaces. These inventories are expanded below so a successful Mac compile cannot conceal missing product behavior.

## Media and privacy-adapter checkpoint — 2026-11-25

This remains the **same Neb app and monorepo** on Windows and Mac, not a separate product. After the explicit detector-policy question, the owner answered: “everything like the windows just for mac compatible, but it's the same app for both.” Ruling: match Windows' bounded known-signal policy on Mac; do not represent it as universal call/share absence. Unreadable signals, unbound browser identity and unknown private context still refuse capture. No screen-reading service has been enabled merely because this policy is approved.

- Native media now has a real worker for running Spotify and Apple Music, using their public scripting interfaces with PID and launch identity. Queries start only on an explicit panel open; controls recheck the selected track and playback state. Fixed JXA source never contains player/clipboard text as executable code. Three-second subprocess deadlines, bounded output, cancellation and error handling apply. Denials/timeouts stay visible and stop polling until the user closes and reopens the panel; resize notifications are idempotent. No real player command or Automation prompt was used during automated verification.
- Spotify playlist/album pins use the same validated link/pin format as Windows. An explicit pin action reads bounded clipboard text on main, wipes its owned Rust copy, and sends only the canonical playlist/album URL to Spotify's public name endpoint. One bounded worker handles lookup; cancellation and live local consent are checked before/after async work and before persistence. A failed name lookup keeps a truthful generic name. Six validated local pins persist atomically; open uses only a saved validated target, and unpin saves the real result. Automated tests use fake clipboard/network/open hooks.
- Showing song titles/pins requires the explicit visible-overlays setting, with recording/share disclosure. Pause, revocation, close and Escape cancel the session and clear its visible metadata. Pin refreshes retain a prior player-permission error. Escape ownership is shared across island and drawing, so ending a stroke cannot unregister a music-only island's cancellation key.
- Annotations bind to process launch, window and display metadata. Unknown identity or changes clear/hide notes and release drawing input. One main-queue check can be outstanding; no screen pixels, entered values, titles or keystroke stream are inspected by this watcher. Scroll anchoring and real focus/display matrices remain open.
- Added compiled, separately reviewed privacy adapters: Mac bundle/blocklist mapping and a narrow native AX role contract; bounded CoreAudio input-device plus known-app signals returning `KnownSignalsIdle`/`Active`/`Unknown`; a read-only Chrome mode prototype that remains **Unbound** and cannot authorize a capture window; and a nonce-bound Metal presentation indicator. The indicator uses actual drawable presentation plus fresh visibility checks, with two-second presentation and 15-second lifetime limits. These adapters are not yet connected to a production capture policy sampler or the screen question/study/save orchestration.
- Verification: **392 Rust tests passed, 2 opt-in tests excluded**; **26 overlay browser tests passed**, including Mac native-player display and explicit control/pin bridge actions; Node fixtures cover 10 media and 5 browser-script scenarios alongside the 4 updater-manifest cases. Full repository formatting/lint/type/test checks pass, including all 410 backend cases. Source/security reviews found and fixed denied-media resize retries, stale track controls, Escape ownership, lost failure notices, and concurrent consent revocation gaps.
- The owned Metal fixture initially failed presentation. Initial ordering/pending validation was corrected, and owned native runs have reported `MAC_INDICATOR_PRESENTATION_AND_REVOCATION_PASSED`. The synthetic lease suite passes as well. A later final-binary run also hit the bounded presentation timeout, so native reliability remains open despite those successful runs. Capture stays disabled; no screenshot or user content was captured, and this is not an installed full Screen Coach acceptance result.

**Full Windows feature parity is still incomplete.** In particular: production capture/voice/ask, Circle & Ask/clip/save, study/Watch flows, cursor modes, native Handoff, browser media/artwork, oldest-OS/Intel runtime acceptance, and signed/notarized release/update testing remain open in the detailed ledger. Compiled adapters and synthetic fixtures do not close those requirements.

## Shared logic is not native feature integration

`screen/mod.rs` exports `cursor/` and `handoff/` without Windows cfg gates. Their pure modules are included in the Mac Rust build graph and the merged-source Rust suite passes. That verifies shared test behavior; it does not establish that either feature runs through the installed Mac app.

- Cursor modules: `catch`, `doit`, `engine`, `euro`, `find`, `lesson`, `path`, `plan`, `posterior`, `predict`, `recipe`, `rename`, `replay`, `scene`, `settings`, `settings_uri`, `stream`, `target`, `telemetry`, `trace`. They define algorithms, plans, allowlists, scenes, state, persistence formats and replay fixtures. Windows-only `cursor_run.rs`, `cursor_do.rs` and six cursor-specific native adapters still own real observation/rendering/actions.
- Handoff modules: `context`, `package`, `pickup`, `redact`, `select`, `settings`, `timeline`, plus voice phrase parsing. They define portable context/package/redaction/selection/action policy; Windows-only `handoff_run.rs`, DPAPI/CNG/image/git adapters, URI registration, preview commands, setup and deep-link dispatch still own production execution.
- Shared server routes, schemas, viewer, inbox and cached voice cues remain reusable. They are source implementations, not verified deployed endpoints, Mac permissions, native hooks, dialogs, media, input or cryptography. Neither generic Mac `overlay::ensure` nor bundled JavaScript supplies these missing runtime paths.

## Release and update integration

The direct-download requirement includes the updater behavior already present on Windows. Historical notes calling updater scope a “deferred choice” do not override the current full parity instruction.

`updates.rs` already implements the product state machine: first check after 30 seconds, every six hours thereafter, signature-verified background download, progress, ready notification, explicit restart/install in tray/settings and no automatic mid-lesson restart. Debug builds and absent HTTPS feed/key mean updates off. Mac presently loads the plugin but does not compile/start this module or register its commands/menu item.

Extract the settings-window authorization dependency from the Windows-only coach as necessary; retain exact trusted caller. Extend release configuration and `desktop/scripts/update-manifest.mjs`, which currently emits only `windows-x86_64` NSIS entries. Mac updater artifacts/signatures are separate from the customer DMG: validate the exact Tauri-supported Mac update artifact for the selected architecture strategy. Confirm official upstream API/release documentation during implementation. Never place signing secrets in source or logs. Publish neither the feed nor installer before the exact release artifacts and install/upgrade tests are reviewable and publishing is authorized.

## Coherent integration order

This is dependency ordering for completing the full target, not permission to ship partial parity.

1. Freeze source inventories and platform contracts. Preserve Windows behavior/tests while separating OS-neutral orchestration from HWND/COM types. Share existing Mac auth/transport rather than reimplementing identity. Add capability/status reporting that distinguishes absent, permission denied and supported.
2. Connect the narrow native foundation: stable target/display identity, AX secure focus, TCC lifecycle, memory frame capture, indicator, Vision/redaction/encoding and cancellation to fake transport. Close real installed capture/permission acceptance before sending user pixels to a live endpoint.
3. Keep external privacy acceptance open independently.
4. Wire capture-to-ask/intent/voice/ink and Circle/clip/save/destination/notebook readback. Include reanchor, note scroll, text-only Notes Check, walkthrough/skills and quiz rather than treating shared server routes as native completion.
5. Integrate cursor stream/AX targets/native scenes, SHOW ME, all four DO IT chores/replays/undo and all five CATCH ME rules with separate consent, cues, privacy and local state. Include Handoff timeline protection, redaction/preview/Send, flags, native crypto and receiver Pick up/deep links; shared routes alone close none of these. 6. Finish supported media/source adapters in parallel with UI-independent integration if resources permit; close player/browser/timestamp acceptance. Resolve external privacy with controlled receiver evidence; retain unknown/unverified conditions as a release blocker, never silently weaken the claimed guarantee.
7. Integrate full settings/tray/tour and updater, then produce signed/notarized DMG and update artifacts, verify hosted/native version compatibility, clean install/upgrade/relaunch and both OS regression matrices. Close every retained feature item before full-parity release sign-off.
